## 统一执行纪律

每个任务按以下顺序执行：

1. 增加会失败的自动化测试，或先写明不可自动化的可重复验收命令。
2. 只实现让当前测试通过所需的最小代码。
3. 运行任务级测试，再运行当前阶段回归。
4. 更新 OpenAPI、需求追踪和必要的运维文档。
5. 检查 git diff，确认不包含密钥、临时文件、构建产物和无关改动。
6. 完成计划中给出的提交检查点。

每个阶段退出时必须满足：

- Maven 与前端生产构建成功；
- Flyway 可从上一里程碑升级；
- 状态只能通过专用命令改变；
- Controller 不直接访问 Mapper；
- 列表、详情、附件和命令执行相同的数据范围约束；
- 当前阶段全部自动化测试通过；
- 已完成的 FR 和 AT 有可复现证据。

## 范围控制

V1排除范围完整沿用需求规格说明书第15章：

1. 微信小程序、独立H5端、Android或iOS客户端；
2. 真实门禁、RFID、传感器、摄像头或其他物联网设备；
3. 人脸、OCR、AI故障诊断或AI风险识别；
4. 在线安全考试、题库和自动阅卷；
5. 地图、蓝牙定位和室内导航；
6. 短信、邮件、企业微信或飞书通知接口；
7. 支付、押金、计费和发票；
8. 第三方统一身份认证、校园卡或教务系统对接；
9. BPMN工作流引擎和用户自定义审批流；
10. 微服务、注册中心、API网关、消息队列和分布式事务；
11. 多租户及跨学校运营；
12. OSS或MinIO强绑定；
13. 二维码、Excel导入导出和独立全屏数据大屏；
14. 智能推荐、自动排班和预测性维护；
15. 业务历史的自动归档或物理清理。

新增任一项都必须先修改需求、设计、计划和验收标准，不能在实现中顺手加入。
