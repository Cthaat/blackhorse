# G1 预约工作台实施计划

> **For agentic workers:** 使用 subagent-driven-development 按独立任务实施和审查；不创建工作树。用户已选定需求池 G1 并要求开始开发。

**Goal:** 完成开放日历、设备规则版本与模拟、候补占位及确认、授权业务追溯的前后端闭环。

**Architecture:** 保留模块化单体和现有预约事务。普通预约、规则发布、候补邀请／确认均以设备行锁串行仲裁。规则是不可变已发布版本，草稿可修改，旧预约保留版本与快照；没有设备规则时沿用当前全局时间参数。候补转正仍为待审批预约。

**Tech Stack:** Java 17、Spring Boot 3、MyBatis、MySQL、Redis、Vue 3、Element Plus；不增加外部服务。

## 授权范围和决定

- 依据：`docs/requirements/lab-extension-backlog.md` 第四节及 G1。当前不做二维码、信用处罚、组合设备排程、MQ、AI、全量压测或正式求职材料。
- 规则按设备配置，复用 `lab:device:edit` 和设备管理范围；读日历复用可预约设备的读取权限。全局提前量／时长参数继续是安全边界，设备规则只能进一步收窄。
- 一个规则版本含名称、开放星期、每日开放起止时间、关闭日期与原因、提前量、最长提前天数、时长上下限、邀请分钟数。只支持同日开放窗口；没有设备规则时保留原有跨日预约行为。
- 草稿与发布使用乐观版本，发布时持有设备行锁，将旧已发布版本归档。停用恢复全局规则，页面明确提示；旧预约不被自动取消。
- 日历最多查询 31 天，展示每天开放窗口和匿名占用；模拟只读，返回原因码及提示，不占资源。
- 候补只允许本人申请，按入队时间和 ID 顺序处理；同一申请人相同设备时段不能重复排队。邀请占位有期限，过期、放弃或资格失效释放；确认必须再次校验资格、当前规则和安全阻断。
- 候补占位与普通预约使用相同设备锁，普通提交不能越过有效邀请；调度器及释放资源后的处理负责推进队列。重复确认返回已经创建的预约，不重复落单。
- 历史资格未存快照，追溯只能称为“当前匹配资格”；设备／实验室隐患只能称为“相关目标上下文”，不能虚构与预约的因果关系。通知只返回当前用户已收到的消息。
