# G2 可靠后台处理设计

日期：2026-09-05。状态：用户已选定 G2；本书面实现设计待确认，尚未实施。

## 1. 目标与方案选择

交付 EXT-04＋29、EXT-09＋30、EXT-34 的前后端闭环：消息模板与可靠投递、异步导入导出、受限运维页面。沿用 Java 17、Spring Boot 3 模块化单体、MyBatis、MySQL、Redis、Vue 3 和现代实验室工作台。

三个方案的取舍：

- 推荐：MySQL 持久状态＋现有 Quartz 调度＋受控本机工作线程。复用通知事实补偿、对象权限和私有存储；新增基础设施最少，但任务恢复与投递状态需在项目内明确实现。
- Spring Modulith／Spring Batch：减少部分基础机制自研，但会增加框架依赖和现有事务、调度的迁移成本，本批不采用。
- MQ／分布式工作节点：适合后续 EXT-32／38，不作为本批前提，不引入 Docker 或微服务。

只启用站内消息，不真实发送短信、邮件或企业消息。不增加支付、AI、IoT、独立大屏。保留既有数据和历史迁移，使用新的 Flyway 增量迁移；全部工作在本仓库，不创建工作树。

## 2. 消息模板与可靠投递

业务事实仍是通知来源的唯一权威；沿用状态历史、巡检／隐患逾期事实及候补邀请事实补偿，不新增另一套业务事件真相。新增投递登记承担执行状态，原通知表承担收件箱与已读状态，两者不是两个重试队列。

- 补偿解析器按既有稳定去重键登记事件；业务事务提交后的快速路径同样登记，再投递。业务回滚不登记成功事件，提交后进程退出可由事实扫描补登。
- 登记包含事实来源类型／ID、事件类型／版本、接收人、稳定去重键、模板版本、不可变渲染快照、尝试次数、下次重试时间、脱敏错误码及关联号。事实解析时固定候选接收人和内容；登记后重试不按新模板改写旧消息。
- 状态为待投递、处理中、等待重试、已送达、人工处理、已抑制。通过条件更新领取及超时回收，失败按 1、5、15、60 分钟退避，最多自动尝试 5 次。送达后确认丢失时，依靠原收件箱去重键确认，不重复插入消息。
- 既有失败通知迁移到统一登记／重试入口；原调度补偿转为登记器，不继续独立无限重试。已发送消息、已读时间和原去重键保持不变。历史缺失记录按事实补登记并校验已有收件箱结果。
- 人工重放仅针对可恢复失败、可验证存在的合法事实，必须填写原因；保留操作者、时间、尝试和结果。不允许修改载荷、删除审计或借重放重新审批业务。
- 模板支持草稿、预览、发布和历史版本，变量为事件类型的白名单；不执行表达式或 HTML。发布后不可修改，旧消息使用原快照。首次投递按当时有效版本生成快照，缺少自定义模板使用版本化内置模板。
- 渠道页显示站内渠道启用，外部渠道未接入且不可启用；保留渠道接口扩展点。个人偏好只控制可选提醒，审批结果、安全处置和候补限时邀请不能关闭；抑制结果保留原因。

前端交付：个人通知偏好、模板列表／编辑／预览／版本、渠道状态、投递列表／详情／重试历史／人工重放。列表分页、筛选、加载、错误和空态完整。

## 3. 异步导入导出

复用现有 POI 和 StorageService，不使用公共静态目录存输入和结果。

- 导入类型为实验室、设备，提供 XLSX 模板和填写说明。只创建新记录，不通过导入覆盖已有资产；业务键重复作为逐行错误。字段与现有新增 DTO、服务校验保持一致。
- 文件上传后生成持久预检记录，验证格式、列、类型、必填项、业务键、归属与权限；预检完成才能明确提交导入。合法行可提交，界面先显示合法／错误数量；提交时和执行时重新校验，不将预检当作最终授权。
- 导出类型为实验室、设备、预约、维修、隐患，保存固定类型及筛选条件，不接受任意 SQL、字段表达式或服务名。按 ID 稳定游标分批，限定提交时最大 ID；不是跨批数据库一致性快照，报表标明起止时间、筛选条件和生成期间可能发生的数据更新。
- 生命周期：QUEUED → RUNNING → SUCCEEDED／PARTIAL／FAILED；取消请求进入 CANCELLING → CANCELLED。排队任务可直接取消。导入取消保留已提交行，不伪称回滚；取消导出不开放半成品下载。
- 导入每行业务写入与该行成功检查点同事务提交，批量领取、逐行事务，避免重启重复创建。取消在行边界检查。合法行和错误行分别计数，错误明细可下载。
- 重试创建关联的新任务，保留旧任务与日志；导入只重试未成功行，已提交结果不可重写。导出重试重新生成，不复用旧结果冒充新快照。
- 任务领取使用数据库条件更新、租约及执行版本，工作者更新必须匹配版本。默认租约 60 秒、心跳 15 秒，重启回收过期任务；导出从头重新生成，导入按行检查点继续。此处验证单实例重启恢复，不宣称完整双实例容错验收完成。
- 默认限制：单文件 5 MiB、5,000 行、最多 50 列；全局待处理任务 100、工作线程 2、每人活动任务 2、每批 100 行、预览最多 100 行、导出最多 50,000 行、输入／结果保留 7 天。超限明确拒绝，导出超限失败而非静默截断。任务计数与入队原子校验，不依赖先查后插的竞态窗口。
- 拒绝公式单元格与宏格式；限制 ZIP 解压膨胀、单元格长度及解析资源。输出将用户内容作为文本，不产生可执行公式。下载只返回私有流，文件过期明确提示，清理不删除业务数据和审计事实。

前端交付：导入模板下载 → 上传预检 → 错误预览 → 确认提交，任务列表／进度／取消／重试／结果及错误行下载；业务列表接入异步导出入口。

## 4. 权限与接口边界

后端继续 DTO → controller → service → mapper 分层。新增接口族为 `/lab/message-templates`、`/lab/deliveries`、`/lab/notification-preferences`、`/lab/tasks`、`/lab/operations`；命令遵守现有 `/commands/...` 风格。分页排序采用稳定 ID 次序和有界页大小。

- 模板、投递操作、运维查看使用独立功能权限，默认授予系统管理角色；投递中心仅展示运维元数据和脱敏错误，不默认开放其他人的消息正文或收件人信息。
- 个人偏好和任务只能本人操作。实验室管理员导入其可管理实验室／设备；实验室创建仍需原新增权限及部门范围。导出必须同时拥有对应业务读取权限和导出权限，不因新增菜单而扩大数据范围。
- 任务保存提交时允许的范围快照；执行时重新加载账号状态、功能权限与对象范围，使用提交范围和当前范围的交集。不得恢复旧角色令牌或以系统账号代替提交者执行。
- 下载再次核对身份、任务归属、功能权限，以及结果所包含对象／部门的当前授权。任一结果授权已撤销则拒绝整个文件并提示重新生成，不能只检查任务拥有者。
- 系统管理角色的运维权限不自动授予实验室业务导出权限；重放、取消、重试、模板发布均保留审计，敏感数据不进入日志。

## 5. 应用健康与可观测性

运维页展示后端、数据库、Redis 状态，以及 JVM、数据库连接池、HTTP 请求数／系统错误率／P95、投递积压及最老年龄、异步任务状态数量／完成耗时。每项附采样时间、来源和统计窗口；无样本或不可用显示未知，不伪造为零。Redis 不可用显示降级，不等同数据库不可用。

HTTP 指标使用低基数路由模板和状态类别，采用有界统计窗口；不以用户、对象 ID 或原始 URL 作为指标标签。业务校验拒绝与服务端异常分开计数。优先使用 Spring Boot 版本管理的 Actuator／Micrometer，新增依赖前核对当前安全链兼容性；管理端点不公开 env、配置、堆转储或完整健康详情，页面通过授权的业务运维接口读取安全字段。

请求生成或严格校验关联号，写响应头及 MDC，持久关联到 G2 投递／任务和操作记录；异步执行继承关联关系，不共享线程残留 MDC。历史记录无关联号时显示未记录，不伪造分布式链路。页面显示积压／失败告警与可定位编号，只提供本地页面告警，不实际发送外部消息。

## 6. 实施顺序与最低验收

按三个连续闭环实施：消息与投递 → 异步任务及导入导出 → 运维页与关联号。每个闭环完成迁移、后端、前端和必要验证后提交，全部在本机原生依赖上运行。统一现有现代工作台样式，不另起视觉方向。

最小验证覆盖：回滚不发消息、提交后中断补投、重复投递去重、重试上限与重放审计；输入校验、错误行、合作取消、重启续行不重复写入、撤权后的执行／下载拒绝；真实指标、管理端点越权拒绝、关联号贯通。使用隔离测试数据，禁止故障注入破坏现有演示记录。

运行后端定向测试和打包、前端定向测试和构建，启动本机前后端并做实际浏览器角色主线及桌面／窄屏检查。全量 E2E、长期压测、正式求职材料留至 G5；最小权限和一致性验证不后置。测试通过前状态只写“开发中／已实现待验收”，不承诺零缺陷。

确认本设计后一次性进入 G2 实施，不在普通编码步骤反复请求确认；新增费用、真实对外发送或范围扩张仍需另行授权。
