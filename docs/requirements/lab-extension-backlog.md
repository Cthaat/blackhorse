# 实验室平台扩展需求池

状态：2026-09-05 用户确认纳入分期需求；本轮只修复现有功能，不实施下表扩展。

V1 基线排除项不是永久放弃项。以下需求从“项目不做”调整为“后续版本候选”；尚未实现，也不计入当前版本已完成功能。每期优先交付前后端闭环，再补完整验收和正式文档。必要的安全、金额及状态一致性验证不能省略。

## 一、建议分期与功能范围

| 编号 | 阶段 | 功能 | 需要开发的前后端闭环 | 依赖与交付边界 |
|---|---|---|---|---|
| EXT-01 | A：无外部依赖优先 | 二维码资产管理 | 设备标签生成、扫码详情、扫码发起预约/报修、管理员核验领还 | 二维码仅含对象标识，不含凭据；扫码仍校验权限 |
| EXT-02 | A | 移动 Web / PWA | 学生预约、消息、报修、整改拍照、管理人员现场核验；响应式导航 | 不承诺离线办理领用、支付等强一致操作 |
| EXT-03 | A | 独立数据大屏 | 实验室分布、设备利用、预约趋势、隐患闭环、任务趋势、全屏轮播 | 使用授权后的聚合接口；不能以匿名大屏暴露个人信息 |
| EXT-04 | A | 消息模板与渠道中心 | 模板版本、变量校验、站内消息配置、订阅偏好、发送记录、失败重试 | 先实现站内渠道及适配接口，外部渠道默认关闭 |
| EXT-05 | A | 安全培训与考试 | 课程、题库、组卷、考试、成绩、补考、通过后申请资格 | 防重复交卷；资格由明确规则/审核授予，不直接跳过现有资格校验 |
| EXT-06 | A | 预防性维护与计量校准 | 维护周期、校准到期提醒、保养工单、停用窗口、报告附件 | 维护与预约占用统一仲裁；保留校准历史 |
| EXT-07 | A | 资产盘点与耗材库存 | 盘点任务、扫码核对、差异处理；入库、申领、出库、盘点调整 | 库存流水不可直接覆写；高风险试剂管理另行审批范围 |
| EXT-08 | A | 科研项目与成本归集 | 项目成员、项目预约、使用时长、耗材归集、预算提醒、成本报表 | 先做内部核算，不连接财务扣款 |
| EXT-09 | A | 业务导入导出 | 实验室/设备模板导入、预检、逐行错误反馈、业务报表导出 | 限文件大小/行数，按权限导出，记录审计，处理表格公式注入 |
| EXT-10 | B：业务协作深化 | 可配置审批 | 分级审批、会签/加签、转交、超时提醒、请假代理、审批记录 | 先覆盖明确业务模板，再决定是否需要 BPMN 引擎；禁止自批 |
| EXT-11 | B | 设备共享开放规则 | 开放时段、节假日、停机日历、黑名单、爽约限制、候补队列 | 原有冲突检测、资格与重大隐患阻断优先于候补和排程 |
| EXT-12 | B | 文件与知识库 | 操作规程版本、培训资料、设备说明书、全文检索、有效版本提示 | 原文件权限贯穿搜索与下载；支持后续对象存储适配 |
| EXT-13 | B | 多实验室预约排程 | 组合设备申请、批量时段、课程预约、容量约束、人工确认排程 | 必须明确部分成功/全部成功及资源锁定规则 |
| EXT-14 | B | 审计归档与备份恢复 | 历史归档、审计检索、保留期配置、备份任务及恢复演练入口 | 管理员不得通过业务页面篡改已完成的审计记录 |
| EXT-15 | C：第三方接入 | 微信小程序 | 身份绑定、设备查询、预约、消息订阅、报修和整改照片上传 | 需小程序主体、应用配置、合法域名及发布审核；与 Web 复用业务接口 |
| EXT-16 | C | 短信 / 邮件 / 企业消息 | 短信、SMTP 邮件、微信/飞书通知适配、退订、限流、重试和回执 | 需账号、模板审批或 SMTP 配置；发送可能计费，默认沙箱/关闭 |
| EXT-17 | C | 校园统一认证 | OIDC/CAS 等选定协议接入、账号绑定、角色映射、离校停用 | 需学校接口、测试账号及身份生命周期约定，不自动扩大权限 |
| EXT-18 | C | 支付与费用结算 | 计费规则、费用预估、账单、沙箱下单、回调、退款、对账、人工调账 | 需商户及支付渠道；金额用最小货币单位或精确小数；先做沙箱，不擅自启用真实收款 |
| EXT-19 | C | 对象存储 | 本地存储/S3兼容适配、私有下载、临时签名、迁移校验 | 需存储账号；存储供应商不绑死，私有附件不变成公共链接 |
| EXT-20 | C | 电子签署与流程回执 | 安全承诺书、领用确认、验收签署、签署状态及回执归档 | 自研确认与第三方电子签署效力分开标注；第三方接入需主体和合同 |
| EXT-21 | D：智能与硬件 | AI 安全知识助手 | 受控知识库问答、来源引用、按权限检索、对话记录、反馈纠错 | 需模型选择与预算；不自动批准预约、授予资格、解除隐患或代替现场判断 |
| EXT-22 | D | AI 辅助识别与分析 | OCR 资产资料录入、巡检描述整理、故障分类建议、风险趋势摘要 | 输出必须人工确认；上传外部模型前需敏感数据处理和明确授权 |
| EXT-23 | D | IoT 设备接入 | 设备注册、证书/凭据、MQTT/HTTP 接入、遥测、离线告警、规则引擎 | 需协议和硬件样机；先用模拟器，不伪称已对接真实设备 |
| EXT-24 | D | 门禁 / RFID / 用电联动 | 准入白名单、扫码/RFID 签到、进出记录、状态回传、异常告警 | 涉及人身和设备安全；硬件联锁、人工应急和断网策略须先评审，不直接远程切电 |
| EXT-25 | E：规模化后再做 | 微服务架构 | 按稳定业务边界拆分、网关、注册配置、服务调用、链路追踪、消息队列 | 仅在团队/负载确有需要后启用；不能为了技术栈将事务闭环拆坏 |
| EXT-26 | E | 多租户与开放平台 | 学校/机构隔离、租户配置、授权应用、API 版本、签名、配额与 Webhook | 需明确隔离方式与管理员边界；迁移前完成越权及跨租户验证 |

## 二、首批建议

建议首先选 EXT-01、02、03、04、06：二维码、移动 Web、大屏、消息模板、维护校准。它们能扩大实际使用场景，且不要求先购买云服务或硬件。安全培训考试可作为下一条较完整的业务主线。

小程序、AI、IoT、支付、短信邮件均进入需求池，但账号、费用、硬件及外部数据传输的授权不是本次修复的隐含授权。未配置渠道只能呈现“未配置/沙箱”，不能做假成功页面。

## 三、进入开发的最低确认项

每一期只需确认：本期编号、主使用角色、必须完成的业务闭环、外部资源、是否允许真实发送/收费/控制设备。随后补充该期数据模型和接口并开发，保留旧版本可用性；完整回归、性能压测、正式手册和答辩材料在功能完成后安排。

本轮现有功能修复不因这份需求池而变为“全部产品开发已完成”；扩展开发需下一步选定阶段。
