## 1. 文档目的

本文档定义系统V1的目标、范围、角色权限、功能需求、业务规则、状态机、数据要求、接口约束、非功能要求和验收标准，是后续设计、开发、测试、部署及毕业答辩的共同依据。

本文档中标记为V1的需求均属于强制范围。第15章列出的内容不属于V1验收范围，不能在未履行变更流程的情况下挤占核心闭环的开发时间。

## 2. 项目背景

高校实验室常见的管理问题包括：

- 实验室和设备档案分散，设备状态不透明；
- 预约依赖人工沟通，容易出现同一设备同一时间重复预约；
- 预约、批准和领用时难以持续核验安全准入资格；
- 设备领用、归还、故障和维修过程缺少连续记录；
- 巡检任务依赖人工通知，隐患整改和复查难以形成闭环；
- 不同院系、实验室和岗位之间的数据权限边界不清晰。

本项目将设备共享预约和实验室安全巡检放在同一个业务系统中。安全资格、设备故障状态和未销号重大隐患均参与预约及领用判断，使资产管理和安全管理形成真实业务关联，而不是两个独立功能的拼接。

项目现实依据为教育部《高等学校实验室安全规范》和《高等学校实验室安全分级分类管理办法（试行）》中关于责任体系、人员培训、安全检查、风险分级和隐患整改的要求。

## 3. 建设目标与成功标准

### 3.1 业务目标

1. 建立实验室、设备和安全资格的统一档案。
2. 实现预约申请、冲突检测、审批、领用、归还、过期和爽约处理。
3. 实现故障上报、维修处理和实验室管理员验收。
4. 实现巡检计划、任务执行、隐患整改、复查退回和销号。
5. 通过菜单、按钮、部门和业务对象范围实现五类角色的数据隔离。
6. 保留关键业务状态的操作人、时间、原状态、新状态、原因和追踪编号。
7. 为毕业论文和答辩提供可复现流程、测试证据和图表材料。

### 3.2 成功标准

系统同时满足下列条件时视为V1成功：

1. 学生、实验室管理员、安全员、维修人员和系统管理员能够按权限使用系统。
2. 安全准入—预约—审批—领用—归还主流程可以完整演示。
3. 巡检—隐患—整改—复查—销号主流程可以完整演示。
4. 同一设备的有效预约不存在时间重叠，并发测试最多产生一条成功记录。
5. 资格过期、设备不可用、实验室停用或重大隐患未销号能够阻断相关操作。
6. 关键状态变化均可追溯，且不能通过普通编辑接口绕过状态机。
7. 空数据库可以通过Flyway自动建立业务表并加载必要字典、菜单和演示数据。
8. 后端、前端和核心端到端测试通过，阻断级及严重级缺陷为零。
9. Knife4j接口文档可查看、可鉴权调试，并与实际实现一致。
10. 仓库不包含明文密码、Token、私钥、真实个人敏感数据或云服务密钥。

## 4. 系统范围

### 4.1 V1强制范围

- 若依认证、RBAC、菜单、字典、日志、Quartz和代码生成基础能力；
- 实验室与设备档案；
- 学生安全准入资格；
- 可预约时段查询、预约申请、并发冲突检测、审批和取消；
- 预约过期、爽约、设备领用、正常归还和异常归还；
- 故障上报、维修分派、维修过程、维修验收；
- 巡检计划、巡检任务和逐项检查；
- 隐患登记、整改、复查退回、销号和超期提醒；
- 站内消息、角色工作台和基础统计；
- 文件附件、业务状态历史、数据权限和统一异常；
- Flyway迁移、演示数据、自动化测试和部署说明。

### 4.2 复用能力

下列能力复用RuoYi-Vue：

- Spring Security、JWT、用户登录和退出；
- 用户、角色、部门、菜单、按钮权限及数据权限框架；
- 数据字典、系统参数、操作日志和登录日志；
- 通用分页、统一响应、Quartz任务和代码生成骨架。

### 4.3 原创业务范围

- 独立的ruoyi-lab业务模块；
- 实验室、设备、安全资格及其业务关联；
- 数据库行锁下的预约冲突判断和幂等处理；
- 预约、设备、维修、巡检、隐患状态机；
- 领用归还、异常归还和自动报修；
- 重大隐患对实验室或设备预约的阻断与解除；
- 业务对象数据权限、状态历史和核心自动化测试。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 有效预约 | 状态为PENDING、APPROVED或CHECKED_OUT的预约 |
| 时间区间 | 统一使用左闭右开语义[startTime, endTime) |
| 时间重叠 | 已有开始时间小于新结束时间，且已有结束时间大于新开始时间 |
| 安全资格 | 用户在指定实验室或设备类别范围内、处于有效期且未撤销的准入记录 |
| 重大隐患 | 风险等级为MAJOR且尚未销号的隐患 |
| 领用 | 管理员确认用户取得设备并创建使用记录 |
| 归还 | 管理员确认设备返还并关闭使用记录 |
| 数据范围 | 用户根据角色、部门、负责实验室或工单归属可以访问的数据集合 |
| 销号 | 隐患整改经安全员复查通过后的终态 |
| 追踪编号 | 用于关联接口响应、业务状态历史和服务端日志的请求标识 |

## 6. 用户角色与权限

### 6.1 角色定义

| 角色 | 主要职责 | 默认数据范围 |
|---|---|---|
| 学生 | 查询设备、查看资格、提交和取消本人预约、查看本人记录、提交故障 | 本人数据及允许查询的实验室和设备 |
| 实验室管理员 | 管理实验室和设备、维护资格、审批预约、办理领用归还、分派及验收维修 | 所属部门和被授权实验室 |
| 安全员 | 维护巡检计划、执行检查、登记隐患、指派整改、复查销号 | 所属部门和被授权实验室 |
| 维修人员 | 接收并处理维修工单、提交维修结果 | 分派给本人的工单及必要关联信息 |
| 系统管理员 | 管理用户、角色、部门、菜单、字典、参数、日志和任务 | 系统管理数据；业务写操作需同时拥有业务角色 |

用户可以拥有多个角色。功能权限按角色取并集，但业务对象访问仍须满足数据范围和职责分离规则。学生不得审批本人预约，维修人员不得验收本人维修结果，整改提交人不得复查本人整改。

## 7. 功能性需求

### 7.1 系统基础能力

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-SYS-001 | 系统支持账号密码登录、退出及登录状态失效处理 | 正确账号取得JWT；错误密码、停用账号或失效Token被拒绝 |
| FR-SYS-002 | 系统按角色生成菜单并校验按钮及接口权限 | 无lab:reservation:approve权限的用户直接调用审批接口返回403 |
| FR-SYS-003 | 列表、详情、附件和状态命令统一执行数据范围过滤 | 管理员无法通过修改ID读取或操作其他实验室对象 |
| FR-SYS-004 | 固定状态、类型和风险等级使用若依数据字典 | 停用字典项不能用于新数据，历史数据显示不被破坏 |
| FR-SYS-005 | 关键操作写入操作日志和业务状态历史 | 可查询对象、原状态、新状态、操作人、时间、原因和追踪编号 |
| FR-SYS-006 | 系统提供统一异常响应 | 400、401、403、404、409和500具有稳定错误码且不暴露SQL或堆栈 |

### 7.2 实验室与设备

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-AST-001 | 管理员维护授权范围内的实验室 | 实验室编码唯一；停用实验室后不能新建、批准或领用预约 |
| FR-AST-002 | 管理员维护设备名称、资产编号、实验室、类别、型号、风险等级、位置、负责人和说明 | 资产编号唯一；列表支持实验室、类别、状态和关键词组合查询 |
| FR-AST-003 | 设备状态只能通过合法业务命令变化 | 普通编辑不能覆盖状态；非法跳转返回409并保留原数据 |
| FR-AST-004 | 用户查看设备详情和指定时间范围的占用情况 | 有效预约显示为不可用；终态预约不继续占用未来时段 |
| FR-AST-005 | 业务对象支持受控附件 | 单文件不超过10MB、每个对象最多5个，仅允许JPG、JPEG、PNG和PDF；越权下载被拒绝 |

### 7.3 安全资格

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-QUA-001 | 管理员或安全员新增、修改、查询和撤销资格 | 资格包含用户、范围、生效和失效时间；失效时间必须晚于生效时间 |
| FR-QUA-002 | 资格支持实验室范围或设备类别范围 | 目标设备被任一有效资格覆盖时通过，否则被拒绝 |
| FR-QUA-003 | 学生查看本人资格及计算状态 | 正确展示未生效、有效、已过期和已撤销，且不能查看他人资格 |
| FR-QUA-004 | 预约提交、批准和领用时均重新校验资格 | 申请后资格过期的预约不能批准；批准后过期的预约不能领用 |

### 7.4 预约与审批

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-RES-001 | 学生提交设备、预约区间、用途和备注 | 校验通过后生成PENDING预约和唯一编号；24小时内同一幂等键、同一请求体重复提交返回同一reservationId的当前表示，不新增预约或历史 |
| FR-RES-002 | 阻止同一设备有效预约重叠并保证并发正确性 | 20个相同时段并发请求最多一个成功，其余返回409，数据库无重叠记录 |
| FR-RES-003 | 管理员批准或驳回待审批预约 | 批准时重新校验资格、设备、隐患和冲突；驳回必须填写原因 |
| FR-RES-004 | 学生取消本人未领用的待审批或已批准预约 | 状态变为CANCELLED并释放时段；使用中或终态不能取消 |
| FR-RES-005 | 系统自动处理未审批和未领用预约 | 开始时间已到的PENDING在5分钟内变为EXPIRED；超过领用宽限期的APPROVED在5分钟内变为NO_SHOW |
| FR-RES-006 | 各角色按数据范围查询预约 | 学生只见本人；管理员只见管理范围；支持编号、设备、申请人、状态和时间筛选 |
| FR-RES-007 | 预约关键状态产生站内消息 | 审批人和申请人在相应节点收到消息；消息失败不回滚核心事务 |

### 7.5 领用与归还

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-USE-001 | 管理员对APPROVED预约办理领用 | 在配置的领用窗口内重新校验资格、设备和隐患；成功后预约为CHECKED_OUT、设备为IN_USE |
| FR-USE-002 | 同一预约只能领用一次 | 重复领用返回原结果或409；数据库只有一条有效使用记录 |
| FR-USE-003 | 管理员登记归还时间、状况和备注 | 仅CHECKED_OUT可归还；成功后预约为COMPLETED并关闭使用记录 |
| FR-USE-004 | 正常归还恢复可用，异常归还自动进入维修流程 | 异常归还在同一事务内将设备设为FAULT并创建或关联开放维修单 |
| FR-USE-005 | 使用记录不可通过普通编辑接口修改 | 记录保留预约、设备、使用人、办理人、领还时间、状况和超时信息 |

### 7.6 故障与维修

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-REP-001 | 有权限用户提交设备故障 | 生成唯一维修单并将设备设为FAULT；同一设备最多一张未关闭工单 |
| FR-REP-002 | 管理员分派维修人员 | WAIT_ASSIGN变为WAIT_REPAIR，只有被分派人员可处理 |
| FR-REP-003 | 维修人员开始维修并提交结果 | 状态依次进入IN_PROGRESS和WAIT_ACCEPTANCE，设备保持MAINTENANCE |
| FR-REP-004 | 管理员验收维修结果 | 通过后关闭工单并按阻断条件恢复设备；不通过退回IN_PROGRESS |
| FR-REP-005 | 工单详情按时间展示完整过程 | 报修、分派、维修、提交和验收记录及附件均可追溯 |

### 7.7 巡检

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-INS-001 | 安全员维护巡检计划、检查项、受控执行周期、负责人和启停状态 | 周期只能选择每日、每周、每月等受控类型，不能提交任意可执行类名或Cron；缺少检查项或负责人不能启用；停用不删除已生成任务 |
| FR-INS-002 | Quartz按计划幂等生成巡检任务 | 同一计划和执行时间最多一条任务，任务保留检查项快照 |
| FR-INS-003 | 安全员逐项登记合格、不合格或不适用 | 所有项完成后才能提交；不合格项填写问题和风险等级 |
| FR-INS-004 | 不合格检查项生成隐患 | 隐患关联任务、检查项及实验室或设备，任务提交后为COMPLETED |
| FR-INS-005 | 系统识别巡检任务超期 | 截止后5分钟内标记超期并通知负责人，完成后仍保留超期事实 |

### 7.8 隐患整改

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-HAZ-001 | 安全员登记风险等级、影响对象、责任人、期限和要求 | 影响对象必须明确为实验室或设备，责任人和期限必填 |
| FR-HAZ-002 | 未销号重大隐患阻断相关预约提交、批准和领用 | 实验室级影响全部设备，设备级只影响目标设备，并返回明确原因 |
| FR-HAZ-003 | 整改责任人提交整改说明和附件 | 仅责任人或授权代办人可提交，状态进入PENDING_REVIEW |
| FR-HAZ-004 | 安全员复查整改 | 通过进入CLOSED；不通过填写原因并退回RECTIFYING |
| FR-HAZ-005 | 支持多轮整改且历史不被覆盖 | 每轮保存序号、人员、时间、说明、附件和复查结论 |
| FR-HAZ-006 | 系统识别整改超期 | 截止后5分钟内标记超期并通知责任人和安全员 |
| FR-HAZ-007 | 销号后重新计算阻断条件 | 仅在无其他重大隐患、开放维修或停用条件时恢复可预约 |

### 7.9 消息、任务与统计

| 编号 | 需求 | 验收条件 |

## 8. 业务规则

| 编号 | 规则 |
|---|---|
| BR-001 | 实验室编码、资产编号、预约编号、维修编号、巡检任务编号和隐患编号全局唯一 |
| BR-002 | 预约区间采用[startTime, endTime)，结束时间等于下一开始时间时不冲突 |
| BR-003 | 冲突表达式为existing.startTime < new.endTime且existing.endTime > new.startTime |
| BR-004 | 仅PENDING、APPROVED和CHECKED_OUT参与冲突判断 |
| BR-005 | 初始参数为至少提前30分钟、最多提前30天、单次30分钟至8小时；由系统参数配置 |
| BR-006 | 预约提交、批准和领用均校验资格、设备、实验室和重大隐患 |
| BR-007 | MySQL事务及设备行锁是最终一致性手段，Redis不可用时仍必须执行数据库校验 |
| BR-008 | 创建和批准在同一事务内完成设备加锁、资格及阻断检查、冲突查询和状态写入 |
| BR-009 | 状态只通过业务命令变化，普通编辑接口不能接收状态字段 |
| BR-010 | 用户不得审批本人预约、验收本人维修或复查本人整改 |
| BR-011 | 同一预约仅一条使用记录，同一设备同一时刻仅一条未归还记录 |
| BR-012 | 异常归还、设备故障和维修单创建或关联在同一事务中完成 |
| BR-013 | 同一设备最多存在一张未关闭维修工单 |
| BR-014 | 维修人员不能直接将设备恢复可用 |
| BR-015 | 重大隐患按实验室级或设备级影响范围阻断 |
| BR-016 | 单条隐患销号不能覆盖其他未销号重大隐患 |
| BR-017 | 巡检任务以计划ID和计划执行时间建立幂等唯一约束 |
| BR-018 | 预约申请按申请人和X-Idempotency-Key保存24小时；相同键同请求回读同一reservationId的当前表示，相同键不同请求体返回409。其他状态命令使用业务唯一约束和期望状态条件更新处理重复调用，不引入通用幂等表 |
| BR-019 | 核心事务提交后生成通知，通知失败记录错误并允许补偿，不回滚核心事务 |
| BR-020 | 已被引用的业务对象只能停用或逻辑删除，状态历史和过程记录不能普通删除 |
| BR-021 | 服务端、数据库会话和定时任务统一采用Asia/Shanghai时区；API输出带+08:00偏移 |
| BR-022 | 多角色功能权限取并集，但每次操作仍须满足数据范围和职责分离 |

## 9. 状态机

### 9.1 预约

| 原状态 | 操作或条件 | 目标状态 |
|---|---|---|
| PENDING | 批准 | APPROVED |
| PENDING | 驳回 | REJECTED |
| PENDING | 申请人取消 | CANCELLED |
| PENDING | 到开始时间仍未审批 | EXPIRED |
| APPROVED | 申请人取消且未领用 | CANCELLED |
| APPROVED | 办理领用 | CHECKED_OUT |
| APPROVED | 超过领用宽限期 | NO_SHOW |
| CHECKED_OUT | 办理归还 | COMPLETED |

REJECTED、CANCELLED、EXPIRED、NO_SHOW和COMPLETED为终态。

### 9.2 设备

| 原状态 | 条件 | 目标状态 |
|---|---|---|
| AVAILABLE | 领用 | IN_USE |
| IN_USE | 正常归还 | AVAILABLE |
| AVAILABLE或IN_USE | 故障或异常归还 | FAULT |
| FAULT | 开始维修 | MAINTENANCE |
| MAINTENANCE | 管理员验收通过且无其他阻断 | AVAILABLE |
| AVAILABLE或FAULT | 管理员停用，且无未归还记录、开放维修单或未销号重大隐患 | DISABLED |
| DISABLED | 管理员启用，所属实验室已启用，且无未归还记录、开放维修单或未销号重大隐患 | AVAILABLE |

重大隐患作为独立预约阻断条件，不通过伪造设备状态表达。

### 9.3 维修工单

WAIT_ASSIGN → WAIT_REPAIR → IN_PROGRESS → WAIT_ACCEPTANCE → CLOSED。

验收不通过时从WAIT_ACCEPTANCE退回IN_PROGRESS。

### 9.4 巡检任务

PENDING → IN_PROGRESS → COMPLETED。超期作为独立标记，不覆盖主状态。

### 9.5 隐患

PENDING_RECTIFICATION → RECTIFYING → PENDING_REVIEW → CLOSED。

复查不通过时从PENDING_REVIEW退回RECTIFYING。CLOSED为终态，再次发现问题时创建新隐患并关联原记录。

### 9.6 安全资格

状态由生效时间、失效时间和撤销标记计算为NOT_EFFECTIVE、VALID、EXPIRED或REVOKED。

## 12. 接口约束

- 根路径为/lab，查询使用GET，创建使用POST，资料修改使用PUT，逻辑删除使用DELETE。
- 审批、领用、归还、维修验收和整改复查使用明确命令接口，不提供通用状态修改接口。
- JSON使用UTF-8；附件使用multipart/form-data；BIGINT ID输出为字符串。
- 时间采用ISO 8601并携带+08:00偏移。
- 认证头使用Authorization Bearer Token。
- 分页pageNum从1开始，pageSize默认10、最大100，排序字段必须经过白名单。
- 预约申请接口接收X-Idempotency-Key；其他状态命令不接收通用幂等头，重复后的回读或409语义由各命令契约固定。
- OpenAPI和Knife4j只在开发、测试和演示配置启用，文档读取无需业务JWT；调试受保护的/lab接口仍必须携带有效Bearer Token。生产配置默认关闭文档端点。

### 12.2 HTTP与业务错误

| HTTP状态 | 使用场景 |
|---:|---|
| 400 | 参数、时间范围或附件校验失败 |
| 401 | 登录凭据无效、未登录、Token无效或过期 |
| 403 | 功能权限、数据范围或职责分离失败 |
| 404 | 对象不存在或对当前用户不可见 |
| 409 | 时间、状态、重复操作、资格或隐患冲突 |
| 500 | 未预期服务端错误，仅向前端显示追踪编号和通用提示 |

稳定错误码至少包括LAB_RESERVATION_TIME_CONFLICT、LAB_QUALIFICATION_INVALID、LAB_DEVICE_UNAVAILABLE、LAB_LABORATORY_DISABLED、LAB_MAJOR_HAZARD_BLOCKED、LAB_ILLEGAL_STATE_TRANSITION、LAB_DUPLICATE_OPERATION、LAB_OUT_OF_DATA_SCOPE和LAB_REPAIR_ALREADY_OPEN。
